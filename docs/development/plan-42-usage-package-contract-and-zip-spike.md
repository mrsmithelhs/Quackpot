## Work plan

1. Define an explicitly experimental versioned envelope and field allowlist. Separate transport/schema/catalog versions, run identity, evidence completeness, summary and ordered meaningful timeline. Use known synthetic event categories; list each pending production projection mapping. Validate displayed/committed/revealed distinctions and unknown vs zero. Don't require game rules to freeze to test transport.
2. Compare a small locally bundled ZIP implementation (e.g. fflate/zip.js) against required limits using primary docs and exact version/license. Produce a mechanism/dependency note before executable artifact work. Root clears the exact dependency/source acquisition and starting resource caps before any download or execution beyond packet check. Do not hand-roll an untrusted archive parser, use CDN runtime code, run npm install into the game or assume ordinary decompression APIs create ZIP containers.
3. After that bounded mechanism clearance, build pure encode/decode/schema-validation helpers and a report-local diagnostic import page using synthetic fixtures only. Separate archive reading, JSON validation, evidence interpretation and rendering. Producer receives a supplied stable run ID; tests demonstrate simulated save/re-export/new-run behavior without touching game storage. Never render imported strings as HTML or treat a checksum as a signature.
4. Define finite compressed/member/actual-expanded/batch-byte, file/member/event counts, JSON depth/string, retained-memory/work and concurrency limits BEFORE adversarial tests. Enforce actual bytes during expansion, not only claimed archive sizes. Refuse ambiguous members/names, unsupported/encrypted/nested/path-like archives, missing/duplicate usage.json and unsupported contracts. No filesystem extraction. Fail a file with a useful reason while retaining other valid selections. Release buffers/workers/object URLs and support cancellation.
5. Cover normal summary/timeline ZIP round trip; same ID same content vs conflicting versions; distinct IDs/identical summaries; unknown/incomplete fields; corrupted/truncated/unsupported/duplicate members; false size metadata; expansion/batch overload; and display text escaping. Keep total retained synthetic fixtures/evidence at32MiB initially, not realistic giant bomb files. Use a positive control to prove limits/tests discriminate, without unbounded mutations.
6. Show direct local multi-file ZIP import, eligible/excluded/unknown/possible-duplicate counts and a minimal expandable synthetic timeline. This is a contract diagnostic, not a designed classroom dashboard. Measure actual compressed/raw sizes, time and bounded memory on named cases. Browser/device limits stay explicit; no performance/conformance claim from unit tests.
