# Quackpot project seed

## What it is

Quackpot is a browser gacha game used in CourseVGD to teach critical analysis of microtransaction design. Its canonical design is [docs/founding/design.md](founding/design.md). Keep durable design definitions there; this seed records setup context and proposals without copying its tables.

CourseVGD is a user of Quackpot, not a dependency. The two projects have independent repositories and release cadences.

## Owner decisions recorded 2026-10-23

These decisions have been reconciled into the founding design:

- All art begins as SVG source. Per-asset PNG delivery requires a measured reason.
- The experience favors immersion and vibe over explanatory readability, with reduced-motion presentation preserving core information and outcomes.
- The story opens with the player's own named and styled duck, whose silent scenes carry the inner narrative.
- Constraint #2 remains absolute: the game makes no network calls. Runtime CDN loading is not allowed.
- Constraint #3 permits student-initiated download and manual submission of run-usage files to an assignment store. The game performs no automatic transmission; teacher analysis is local.
- Constraint #4: the game is allowed to run long — a floor run of roughly 15 minutes, extendable past a lesson and beyond 15 in-game days; no retention techniques after the Receipt. Saves (autosave chosen on the start menu, or an explicit save icon at many junctures) let runs resume locally.
- All five adopted manipulation-like elements (retention offer, Duck-Dex sets, rival whale, Down shop, pawn offer) are catalog techniques and appear on the Receipt when they fire, so Receipts differ by run.
- Constraint #7 permits Vite for development/build; published output remains static.
- The race has one pre-race choice; fatigue-obscuring approaches remain a request for orchestration recommendations.
- The player's duck may face a late pawn offer and empty-desk scene. Uninstall remains available with the selected retention offer and immediate exit path.

Owner-selected variety, tone names, simulation inputs, candidate near-miss forms, and deferrals are detailed in the canonical design. No unaccepted reviewer suggestion was adopted. GATE-53C has closed; development is underway, and Plan 02's local spike/paths are owner-accepted. The packet index records current status; new assignments and design decisions remain owner-gated.

## Tooling intent and limits

- Host the published game as a static site from GitHub Pages.
- Use Vite for development/build and ship static output. No runtime CDN or network calls.
- The student game has no Bootstrap dependency. Bootstrap remains an allowed future option for the local teacher analyzer; it is not selected.
- Development-time tests and simulation are expected. Draft packets do not authorize implementation; the owner must first approve the sequence, then each packet follows its status and gate.
- Art source is SVG. PNG delivery is considered per asset based on measured fit. Music may be generated by vanilla JavaScript or supplied as locally stored generated files; provenance remains open.
- Teacher analysis imports multiple student usage files locally. Students may manually submit downloaded run-usage files to an assignment store. No automatic upload or cloud synchronization.
