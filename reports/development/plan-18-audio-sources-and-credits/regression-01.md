## Results (all PASS in the final run)
Phase A, in page (21 checks): export keeps the empty `Main` and the empty active `soft` pool and does not emit untouched purposes; clear removes raw storage; import restores `Main (0)|soft (0)` with `soft` active; the export text round-trips exactly (ignoring `exportedAt`); raw storage holds the same pool records; an earlier-format export (non-empty pools only) still imports and saves; **22 invalid imports** each left UI, export text, counts and raw bytes unchanged with "Import rejected; nothing was changed": `fileIds` as a string, `schemaVersion` 2, missing version, foreign schema, non-JSON, pool names `__proto__` and `constructor`, role `__proto__`, notes key `__proto__`, top-level `__proto__` with a payload, nested `constructor` in a pool record, trim as string / −40 / `1e999` / +6, duplicate pool records, two active pools in a purpose, duplicate ID in a pool, an ID with spaces, a rejected-and-pooled conflict, a pool name with a leading space, a non-string note; raw bytes identical after the whole batch; no prototype pollution; a valid import over existing choices only shows a confirmation panel (state and raw unchanged while pending); Cancel leaves UI and raw unchanged and clears the panel; Replace applies and persists; with `setItem` throwing, Replace is NOT applied, UI and raw are unchanged and the message is "Import NOT applied" (never "Import failed"); a pool preview whose file is missing says "Requested…" then "Could not play from pool…" with the error class and never "Played"; a working file says "Playback started from pool…"; the Credits tab lists both music records (creator, source, exact license link, credit text, changes) and still all 63 effects.
Phase B, across reloads (31 checks): for each of invalid JSON, a foreign schema and an unsupported `schemaVersion` saved in storage: the raw bytes are untouched at load, the status is an error, edits (tick, shortlist, note, add pool) leave the raw bytes unchanged with "Not saved", the page stays usable in memory, and the banner offers download and discard; while blocked an invalid import is rejected, a valid import needs confirmation and warns it overwrites the unreadable data, Cancel keeps the bytes, a storage error during the replacement leaves them intact, and a confirmed import writes canonical data and re-enables saving; a stale-revision save with an unknown ID (`qp18-9999`) loads without reset, **Mark reviewed with failing storage is not claimed** (raw unchanged, notice stays, error status) and with working storage saves the new revision and keeps the ID; the earlier saved format (pools as a keyed object, with an empty pool) loads without rewriting, and its first edit rewrites it as the canonical array form with the empty pool and note kept.
Smoke after the final edit: 8 random previews drew only ticked files with no immediate repeat; Stop all, tab switch and rejection behave as before; a mock reports "(starting…)", "(not yet requested)" and then "(playback started)" per voice; a fresh tab has a clean console and renders 66 cards and 65 credits entries.

## Defect found and fixed by this run
A top-level `__proto__` key was ignored and the file accepted. The validator now scans the whole parsed JSON (bounded depth/size) and rejects `__proto__`, `constructor` and `prototype` anywhere as keys; the case and a nested variant are in the suite.

## What this does not prove
Not run from `file://` (owner-accepted skip), in Firefox or Safari, or with a screen reader; nobody listened, and "Playback started" only means the media element reported playing; the 3-voice cap and the browser autoplay-block message remain code-reviewed only (the preview in the final smoke used a synthetic click in a tab that already had user activation). A harness note: one smoke assertion initially read false because the page still held pool entries from the last staged test in memory; the re-run in a clean state passed.
