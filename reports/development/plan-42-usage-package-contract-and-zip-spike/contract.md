# Experimental synthetic usage contract v1

This report-local experiment is not a production export format. A ZIP contains exactly one root `usage.json`, UTF-8; no ZIP64, encrypted, path-like, directory, symlink, descriptor or unsupported members. Schema `quackpot-synthetic-usage` / version 1 / catalog `synthetic-1` accepts only explicitly labelled synthetic records and a caller-supplied `synthetic-` run ID. No name, free text, reflection, seed, exact timestamp or persistent installation identifier is accepted. The run-ID persistence/new-run lifecycle remains a production adapter decision; this spike does not touch storage.

The record provides `evidence` (`complete`, `incomplete`, `unknown`), four nullable counts (`displayed`, `actions`, `committed`, `revealed`), timeline coverage (`full` or `partial`), and ordered timeline events with a synthetic catalog code. Null means unknown; zero requires complete evidence. Complete requires an ordered terminal/Receipt pair at the end with matching synthetic code. A reveal references one earlier committed outcome and can occur only once. Full coverage requires counts match represented events; partial coverage allows larger recorded totals. Counts for incomplete evidence are recorded counts, not proof that unrecorded events never happened. These rules are provisional contract mechanics, not assertions that current game data already conforms.

Production projection remains unimplemented: map cue/offer/retention display, player action, draw committed (including recorded pre-draw odds), reveal shown, terminal and Receipt evidence from the authoritative append-only log after their owning specifications settle. Preserve displayed versus committed; do not derive live odds or events from final state. Compare selected files only: a repeated random ID suggests a possible same run, a changed content projection is a conflict or later snapshot, and different IDs do not prove different students. Neither a CRC nor the ID authenticates the content. Teacher discussion of effect remains a question, not a causal finding.

`usage-contract.mjs` is a bounded duplicate-key-rejecting JSON parser and synthetic schema; `archive.mjs` manages ZIP and byte checks; `interpretation.mjs` compares submissions; `diagnostic.mjs` renders using text nodes. All are experimental and report-local. The browser page uses sequential dedicated workers with a 10-second deadline, capped file/batch input and output; on a worker timeout it conservatively consumes its remaining reservation because the actual work is unknown. No teacher CSV, upload, real data, production integration or production storage is implemented.

A partial timeline is self-contained for represented reveals: each revealed event must retain its earlier committed event. An omitted reveal does not establish that no outcome was committed or displayed elsewhere.
