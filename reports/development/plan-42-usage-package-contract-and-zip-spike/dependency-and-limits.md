# Dependency and adaptation notes

`@zip.js/zip.js` 2.18.0, BSD-3-Clause, registry tarball SHA-512 `xv0lRTXFZQkDu88HkxXY4FfHEVfhA+KzxOARye0kDBZvylP1tJ15v99qiTq1Mm30WxakxKIySk9uVVrwSXkdZA==`; upstream license and pristine package inspected under `inspection-2.18/package/`. The rejected 2.8.23 inspection remains in `inspection/package/`; it is not imported. The local runtime imports `vendor-2.18/lib/zip-core.js`. Its only local ZIP reader change is a pre-parsing rejection at the existing `requiresZip64` branch; pristine reader SHA-256 AC7E8A74C7D740B2D496C04A172F13575AA0D644F0A01933BE52A6ABF53CC0B5 and adapted reader SHA-256 9F4D28DED70866C8BC07B6CB96DD47F94CD915691A9F9FB8A40BEE70CEF0E5C3. `guarded-codec.mjs` is adapted from the pinned WASM stream wrapper and applies an output limit before copying or queueing during both processing and flush, plus an actual-produced callback. It is configured as the sole fallback for the named worker path; no nested library workers or native decompression are selected. Exact bypass freedom across all browser variants remains subject to review and browser evidence. Raw WASM is read locally from the pinned inspection tree, with the upstream license retained.

The input archive is limited to 8 MiB, per-file actual output 2 MiB, selected compressed batch 32 MiB, actual expanded batch 16 MiB, 20 files, one worker, 2,000 timeline events, depth 12 and 512 UTF-16 code units per string. Imported archives are never extracted to disk. ZIP CRC is corruption detection, not authentication. Fixed codec wrapper input/output buffers are each 64 KiB; actual WASM internal heap and whole-browser memory are not claimed as hard capped. Reader directory data is buffered before enumeration; archive length and each read request are capped, but peak whole-browser memory has not been established.

WASM allocation clarification: inspection of the pinned `.wasm` memory section found one memory with minimum and maximum both 258 pages of 65,536 bytes (16,908,288 bytes). A subsequent bounded direct real-codec test observed that exact `memory.buffer.byteLength` before and after its 100,000-byte round trip and output-limit rejection. This is a bound on the module's linear memory, not all JavaScript, browser, worker, ZIP reader or system allocations. The manually inspected module section and targeted observation do not prove an end-to-end browser heap bound.
