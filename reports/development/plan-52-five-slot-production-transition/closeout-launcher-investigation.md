In `reports/development/plan-25-desk-phone-art-integration/bounded-node-run.ps1`, `Plan25ProcessTree.Run` catches `ArgumentException` when obtaining a descendant's start time and `InvalidOperationException` around memory sampling, while Windows access failures can throw a different exception. `SnapshotParents`, process start, kill, wait and output-drain operations can also fail. The outer `finally` attempts owned-tree cleanup, but an exception escaping the method prevents the PowerShell caller receiving a structured receipt. This makes an access-denied descendant read a plausible source of the observed failure; the exact throwing operation and its native error code were not captured, so the cause is not established.

## Narrow tooling proposal

Under a separate orchestration-approved sole-writer tooling scope, retain the existing 90-second, 1-GiB Node heap and 2-GiB sampled-tree thresholds, capped output, PID-plus-creation-time identity checks and prohibition on touching unrelated processes. Wrap each owned-process phase (start, snapshot/enumeration, identity capture, refresh/memory read, termination, wait, output drain and handle disposal) with narrowly scoped error capture that records phase, operation, exception type and native error code when available. On an unexpected inspection or access error, stop the job, attempt cleanup of the owned root and independently verified captured identities only, and return an explicit failed structured receipt even when cleanup itself is incomplete. A receipt must distinguish process exit from unverified cleanup, observed residuals, inspection failure, timing/memory stop and incomplete output. It must never silently skip an inaccessible live descendant, claim a clean tree from incomplete coverage, delete a retained profile or relax any bound. Exclude process command lines, profile paths and other private host data from committed evidence.

Before another Chromium run, review the exact patch and exercise harmless controlled child-process scenarios under fresh host preflight: normal success, a deliberately induced sampling/identity error, bounded timeout, launch failure and a child exit race. Verify structured failure receipts, correct exit status, preserved output cap, no unintended process termination and cleanup qualification. If a failure cannot be induced safely or ownership cannot be proven, record the unobserved case rather than claiming coverage. Only then consider a fresh source-pinned headless browser job with explicit per-job port/root/profile-identity receipt written before risky work. This proposal does not authorize production source changes, a replay waiver or a browser retry.
