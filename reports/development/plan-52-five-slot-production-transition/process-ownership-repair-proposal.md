# Checkpoint browser owned-process tracking — read-only repair proposal

Status: proposal only; no tooling modification or browser rerun authorized. During the first rent-display checkpoint chunk all six continuations completed, but cleanup failed closed with residual/uncertainty because its tracker recorded PID 25824, created 08:11:16, as a descendant of PID 24608, created 15:39:32. The alleged parent was created more than seven hours after the child; root 26568 was created 15:39:23. A later read-only CIM lookup found none of those PIDs. The original cleanup status stays failed/uncertain; no process was killed and the unidentified temporary profile was not removed. The trace lacks exact profile identity, so the directory cannot safely be identified retrospectively.

## Problem and ownership

`scripts/dev/checkpoints/process-tree.ps1` currently seeds the numeric root PID whether or not it exists and follows numeric PPIDs without comparing creation identities. If Windows reuses a PID, an older unrelated process can appear under a new parent. `process-tree.mjs` retains the false identity, and `cdp.mjs` conservatively refuses profile removal when it remains. Its final root-only snapshot after browser exit can also discover unrelated processes using a reused root/parent PID. Current `taskkill /T` can traverse Windows' numeric process hierarchy outside the verified identity set, so verifying only the root is insufficient to prove that every target is owned.

## Minimal proposed contract

1. Capture the live root as a PID plus UTC creation-time identity at launch; carry that identity into every snapshot. If that exact root is absent or replaced, discover **no new descendants** from it. Keep retained previously verified identities separately and query them by PID plus creation for orphan observation.
2. Build child edges only when a candidate parent's PID and captured creation are a currently verified identity and the child's UTC creation instant is not earlier than the parent's. Use an unambiguous numeric UTC tick or ISO timestamp, never locale-formatted string ordering. Equal timestamps require conservative policy because coarse clock resolution cannot prove identity; document test coverage and error behavior. Prevent late unrelated numeric parents from entering the owned set.
3. Prefer graceful CDP Browser.close plus identity-checked observation. Remove blanket `taskkill /T`; for a timed-out process, either use OS process handles retained since launch and identity-safe termination of known handles, or fail closed and report residual without force-killing. A fresh PID check followed by PID-based termination has a time-of-check/time-of-use race and alone cannot establish safety. Any future stronger termination approach needs a separately reviewed handle ownership design.
4. Capture future browser profile path/identity only in a private local diagnostic record controlled by the launcher, with no public absolute user paths; public trace should contain a redacted identifier and hash, plus explicit cleanup outcome. Never retrospectively guess or delete this run's unidentified directory.

Verify cleanup never targets an unverified process; a failing identity/inspection path reports uncertainty instead of deleting a profile. Test actual Windows process and browser cleanup in a fresh isolated attempt only after root allocates a bounded turn. Each Node/browser command uses the existing preflight/launcher/resource boundaries. Existing terminal test output and old 13-checkpoint evidence cannot be relabeled as clean due solely to graph fix.
