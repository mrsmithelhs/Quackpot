# Injury susceptibility adapter — implementation and requested gate

No new job has run. `injury-susceptibility-adapter.mjs` is a report-local copy of the corrected provisional `multi-contact-adapter.mjs`: it adds an optional participant injury hook only inside an actual resolved duck-contact event, delegates keyed roll policy to `injury-susceptibility-state.mjs`, applies successful injury's 0.95 factor on final target beginning the next tick, and corrects leader-slowdown counterfactual for the same effect. Disabled injury must match the corrected traffic adapter's full output, including audit/events/draw keys. The input validates policy `first` or `contact`; absence of the option is injury-off. Existing actual impulses, contact rearm, risk-conditioned advice, course limits, finish and transaction/guard code remain the baseline. Snapshot/rollback must restore participant flags and discard tentative roll evidence in the original tick transaction; this is a code-design expectation, not yet established live-state rollback evidence.

Each initially healthy participant's first actual contact uses identical `(seed,raceId,actualContactId,entrantId)` keyed roll in both policies; first arm stops rolling that duck after its first eligible contact, contact arm rolls each later distinct contact until first injury. Per-race/entrant flags are local to a resolver invocation; no status stacks or re-roll on continuing overlap. Post-injury target applies once from the next tick; a duck's actual collision, place or crossing is never fabricated. This exploratory single-race adapter does not commit persistent injury, handle already-injured entrants, award growth or model life. `extensionOnce` is an isolated pure prospective check of a once-per-completed-race extension, not integrated production or sequence evidence. Unresolved outputs contain tentative internal evidence and cannot be read as committed persistent status.
