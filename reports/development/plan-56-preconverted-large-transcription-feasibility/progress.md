## Actual source and local observations

The upstream build requires CMake >=3.24, Ninja, C++23 and Vulkan SDK headers plus `glslc`. The documented Windows preset uses clang-cl and a Visual Studio developer environment, with LLVM tools for CPU variants; the simpler baseline can disable variants. The shader generator is a nested build: compiler and resource compiler must also be discoverable in its environment. Explicit `MUSCRIPTOR_VULKAN=ON` is necessary to avoid a silently CPU-only build. Vulkan is the documented Windows GPU path; CUDA installed for Plan53 does not establish it. No validated local compiler or SDK was found on PATH or in the checked standard locations; `C:\Windows\System32\vulkan-1.dll` and `vulkaninfo.exe` exist, which proves neither a usable driver/device nor SDK. C: reports 289,581,240,320 free bytes in this sandbox; this is a point-in-time observation, not a reservation. Host GPU availability and compiler installations outside inspected paths remain unknown.

The pinned loader opens GGUF metadata without tensor allocation, allocates a backend tensor buffer, then reads and uploads one tensor at a time through a host staging vector; it does not show the PyTorch full-F32-model-then-cast sequence. It still creates backend weights, F32 KV cache, graphs/scratch, CPU conditioning copy, staging buffers and driver allocations. Upstream estimates weights 2.739 GB and Large KV about 1.5 GB, approximately 4.24 GB decimal together, *excluding* those other costs and existing device use. Neither the peak nor 8 GB laptop fit is established. Explicit device index fails if unsupported/unavailable, whereas Auto can choose CPU; use the former, verify backend/name in the same process, and stop on mismatch. Initialization is not cancellable; later loading polls cancellation per tensor. Sampling can miss spikes and a host process stop is not proof of driver cleanup.

The public API takes 16 kHz mono float samples and returns notes; caller handles decoding, resampling and MIDI. It uses five-second chunks, prelude/tie forcing by default, sorted note output and finite token/KV limits; a chunk hitting the limit can return without EOS. Programs, drum flag, pitch and onset/offset must be preserved; predicted velocity is absent. Drum-token hits have a 10 ms minimum, while program 96 is routed as drums with decoded offset. Report cleanup/omissions, quantization/rounding and chunk-boundary treatment. [API](https://raw.githubusercontent.com/DamRsn/muscriptor.cpp/34a01513f3edfacf21fba7849859b703a6e2a9df/docs/API.md) and [performance](https://raw.githubusercontent.com/DamRsn/muscriptor.cpp/34a01513f3edfacf21fba7849859b703a6e2a9df/docs/PERFORMANCE.md) describe device fallback, precision and memory.
