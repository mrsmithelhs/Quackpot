## Evidence and remaining choices

The frozen integer study matched all 11 canonical outputs across one Node/Chromium pair; the promoted source passed 25 focused tests including four exact golden-byte comparisons. These finite cases do not establish universal portability, balance, v1 parity or full save replay. The worker study's focused tests passed 4/4; one browser batch at desktop and narrow sizes matched the frozen result through both representations and observed responsive fixture controls. The browser job exited 1 because strict cleanup remained unverified, despite successful artifact checks. See `worker-study/findings.md` and its pinned receipts for source, test and cleanup details.

One mixed-race sample measured 286,790 canonical bytes, a 9,327-byte compact record and a 74,663-byte gzip/base64 full-result record. Compact stores versioned input, selected facts and a canonical-result digest; a worker recomputes and checks the result and facts. The digest is not authentication: replay must independently derive authoritative input and effects from the run history. Full-result gzip also reconstructs and compares the complete canonical envelope, with explicit compressed/decompressed bounds. Prefer compact for the next integration turn, subject to root acceptance and actual multi-race evidence. The illustrative 1/10/30/60 projections include a labeled historical v1 whole-save baseline and proxy log growth; actual v2 log growth and browser quota are unknown.

Single-race reconstruction took approximately 1.33–1.45 s in the isolated browser on this host. Serial extrapolation to 60 races is roughly 80–87 s, not an observed long-history result or an acceptable boot guarantee. Root should choose an explicitly bounded asynchronous restore strategy, user-visible progress/cancellation and failure behavior, with actual multi-race throughput and responsiveness evidence before owner-ready delivery. The study worker currently prepares both compact and compressed representations for a new result; a production compact-only path must not unnecessarily require gzip support. Browser APIs and supported-environment behavior need source-bound testing. The client validates a candidate's structure and epoch; it does not itself authorize engine state or independently establish that inputs came from history.
