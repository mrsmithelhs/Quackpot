# Integer feasibility — expanded Node probes

The fixed-input Node suite passed nine tests under the unchanged bounded launcher: exit 0, 0.550 s, sampled owned-tree peak 4,943,872 bytes, no stop or cleanup note; fresh host preflight 12.74 GiB. The earlier Decimal generator and first Node result are recorded in `findings-v1.md`. The expanded protocol was amended before each additional fixed set; its earlier hash in `findings-v1.md` is historical, not the current hash.

- The nine Decimal rotation vectors showed a maximum component difference of 22,072,402,700 Q62 ticks, about 4.7862e-9 unit vector. Integer vectoring on the same nine inputs differed by at most three turn ticks. Four exact axes and diagonals, small/zero/oversized vectors and signed wrap were exercised. These are finite observations, not a proved error envelope.
- Integer square-root floor inequalities were checked at 0, 1, 2, 3, 4, 15, 16 and 2¹²⁷−1. Ties-to-even division, checked limits, malformed/oversized canonical probe serialization and unpaired-surrogate keyed-input rejection were exercised. The canonical schema is a **small probe**, not a game save or tamper-proof protocol.
- Fixed oval start and three joins, straight/bend position-to-contact threshold examples, rating/rest/Down/injury composition, exact toy contact/finish ordering and adjacent finish thresholds were exercised. These are instantaneous fixed probes, not swept contact, an integrated race, or proof of branch stability at all boundaries. A 2,000-frame microbenchmark took 11.519 ms in this Node invocation; it is not full-race performance or a cross-device claim.

At this boundary, rotation, vectoring, integer square root, fixed course-frame examples, threshold decisions, canonical probe strings and keyed probes exist. Still missing before any implementation recommendation: independent quantified error coverage beyond fixed samples; integer controller, swept/substep evolution, wall/correction, Bounce/crowd/injury and true crossing integration; bounded full-race performance; versioned event/result serialization and meaningful tamper checks; and a pinned Node/browser comparison. The CORDIC table's regeneration has been described but not independently regenerated in a second environment. No portable numerical policy or production source change follows from these probes.
