## Implemented path

`?race-v2=1` selects a separate development storage namespace (`quackpot_save_v2_development` and its backup). Default startup remains the prior schema-5 path. In the opt-in, restore begins with a bounded raw read, then a serial owned worker queue reconstructs each compact race from an input independently derived from earlier draws, choice, rest, schedule entry day and growth/injury history. The app does not hydrate its engine until this and synchronous structural reconciliation finish. Progress, real Settings and a non-destructive leave control are available while waiting. Unsupported, corrupt, unavailable-worker, external-change and quota paths preserve existing data; explicit replacement attempts a separate-key backup. Schema-5 storage is never read or cleared by this path.

The worker's production resolution path produces compact records only. `worker-client.mjs` checks the returned envelope and independently reconstructs its compact projection before candidate claim. The private session binds an engine object, a detached exact event-log prefix, worker-verified candidate objects and the exact stored bytes; appended races must carry a verified worker candidate and pass history/effect checks. Existing candidates are reused for ordinary autosaves rather than numerically rerunning all races. Full reload still reconstructs every race. Cross-tab storage changes invalidate the session. One race preparation snapshots full engine state, log and RNG, stages admission/recovery before entry, then checks the epoch again before publishing the draft. Cancellation and stale results do not publish race effects.

The draft progression helper applies the selected two-day recovery, same-race retained player injury, finished-only +2/+1 progress, one first-point bank/one-time Bounce or crowd assignment, payout and entry-injury-only 25% extension. New injury after entry is not decremented for an earlier elapsed day. The common transaction publisher handles elapsed day changes; the race draft marks recovery already staged. The result path uses an explicit development outcome inspection view; accepted race visual playback and ability-selection UI remain unmounted. The SHA-256 digest and FNV event chain are integrity evidence, not authentication of human activity.
