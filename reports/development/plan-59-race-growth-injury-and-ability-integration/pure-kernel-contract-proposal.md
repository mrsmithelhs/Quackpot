# Plan 59 pure kernel — proposed contract for review

## Surface and dependencies

Propose `resolveRaceV2(input) -> result` as a synchronous, pure, bounded function in new `src/core/race-kernel-v2.mjs`; invalid input throws a typed validation error before simulation. No caller-owned object mutation, clock, browser, storage, UI, ambient randomness, report imports or I/O. Proposed sole runtime dependency initially `src/core/prng.mjs` (pinned at the actual slice gate); any additional production dependency must be enumerated and cleared. Study adapter imports thirteen report-local modules; their algorithms must be deliberately reimplemented in cleared production-owned paths, not imported wholesale. If this cannot be done legibly in one module, propose explicit additional helper paths before writing. Tests and study comparison may read reference adapters only in test/report code, never as runtime dependencies. Existing `src/core/race-resolver.mjs` is a read-only reference, not a production dependency of v2, unless root approves a specific seam.

Input proposal, with exact property names subject to root review:

```
{ schema: 'quackpot.race-input/v2', rules: 'plan59-working/v1',
  numericPolicy: <explicit approved version>, seed: nonemptyString, raceId: stableString,
  choice: 'steady' | 'sprint',
  entrants: [{ id, player, lane, row, baseRating, restFactor, downFactor,
               entryInjury: boolean, ability: null | 'bounce' | 'crowd', stance }],
  course: <approved immutable Plan23 configuration identity> }
```

Entrant IDs unique, exactly one player, finite bounded numeric values and supported stances/configuration; reject duplicate/unknown identifiers, missing explicit numerical policy and unsupported rule versions. `baseRating × restFactor × downFactor × injuryFactor` (injury factor .9 only while injured) precedes `8.25 + 0.5 × rating`; exact existing rest/Down order and treatment must be verified at the write pin. Same-race onset updates subsequent target/cap computation without forcing instantaneous speed. No selected later progression thresholds or nine other abilities enter the input. Race-entry injury and participant identity are immutable snapshots; ability assignment/reward/recovery extension remain engine responsibilities. Seed derivation is keyed by version, race, event kind, ordered participant IDs, opportunity/contact episode and participant, not UI timing; pin the encoding and distinguish independent rolls before adoption.

Output proposal:

```
{ schema: 'quackpot.race-result/v2', rules, numericPolicy, raceId,
  status: 'finished' | 'unresolved', inputIdentity,
  entrants: [{ id, entryInjury, effectiveRatingEvidence, finalInjury }],
  events: [{ id, tick, boundaryFraction, kind, participants,
             outcome, rollEvidence, start, endOrCancel }],
  crossings: [{ participantId, tick, fraction, place }],
  trajectory: <bounded sampled motion>,
  retainedInjuries: [{ participantId, eventId }],
  unresolved: null | { reason, lastCommittedTick, guardEvidence },
  serializationVersion: <explicit approved version> }
```

Events distinguish opportunities, activations, termination, actual contact, injury and wall/crossing facts. IDs and event order are deterministic and participant-specific; graphics cannot create events or consume RNG. A finished result requires real individual crossings and authoritative ordered places; payouts may be calculated by engine from a versioned actual placement policy, never by presentation. An unresolved result has no completed classification/reward; crossings already observed are factual partial evidence only. The engine validates size/shape/identity and persists the committed result and entry snapshot once. Separate serialization/restore functions must reject malformed, nonfinite, over-bound and unsupported versions; do not assume v1's 512 KiB ceiling accommodates v2 until measured and approved. Result format is a design contract, not claim of already implemented fields.

## Boundary and rollback contract

Within each tick retain a complete snapshot of participant physical state, event/episode state, draw identity, ability/rearm state and output lengths. Establish an explicit ordered set of candidate event fractions and deterministic tie order before committing effects. Genuine contacts at or before a crossing must be resolved consistently with the accepted individual-finish policy; already-finished entrants are handled according to an explicitly pinned v1 continuation policy. A candidate that would require unsafe separation across corridor/finish or leaves ambiguous/unrearmed overlap ends unresolved rather than forcing a crossing. On a failed endpoint transaction restore all affected state, references, draw records, event records and collision/injury evidence to the last validated boundary. Retain only independently validated earlier injuries, never rolled-back/discarded candidate injuries. Do not credit a finish that exists only in a rejected boundary.

One physical pair/boundary is reconciled once; rearm requires the separately approved separation and tick conditions. A genuine non-closing occupied landing can be a contact without applying an invented closing impulse. Bounce phase includes landing in full protection, keeps pre-existing injury and existing velocity/recovery impulse; each unprotected participant has an independent eligible injury roll. Crowd eligibility is calculated from real, grounded, unfinished nearby participants; activation and termination are recorded separately from graphics. Exact simultaneous contact/finish precedence, stable contact keys, which intermediate boundaries are commit-safe and whether every entrant can own either ability are open to root's technical clearance; test each explicitly rather than guessing from the study fixture.

## Numerical strategy alternatives — selection pending

1. **Canonical output quantization only:** preserves v1-like physical evolution and may stabilize some cosmetic representations. It cannot guarantee identical branches, contact, injury or winner and can hide tampering below its precision. Insufficient alone for a cross-runtime decision guarantee.
2. **Versioned rounded state/decision boundaries:** define rounding at every named state transition and comparison, numeric ranges, signed zero and tie policy, and deterministic implementations or bounded tables for transcendental operations. Assess error accumulation and branch sensitivity; rounding only at output or selected comparisons does not guarantee consistent preceding state.
3. **Versioned fixed-point/integer core:** define integer scale, rounding, overflow and deterministic geometry/trigonometry for all decision-affecting operations, with separately derived display coordinates. Stronger route to reproducibility but potentially larger physics and parity change. Must measure error, boundary decisions and accepted race controls rather than assert equivalence.

Recommend QP Orch select an explicitly versioned decision/evolution contract after feasibility assessment, not a blanket epsilon. A candidate may be built unmounted for comparison only under explicit clearance; production mounting and historical v1 replay remain separate decisions. Serialize exact discrete facts and the selected canonical numeric representation; protect all meaningful fields in the existing validation model and retain negative controls. Hashes detect changes relative to a trusted record, not adversarial authentication.

Cross-runtime paired test inputs should include below/equal/above contact and activation thresholds, landing rearm, near-equal crossings and reversed IDs, injury onset before a finish, rollback at same tick, and nonfinite/overflow rejection. Compare all mechanical branches and discrete outcomes, not just digest or winner; also test altered seed, participant, injury, placement, event and significant numeric field rejection. Compare a finite v1 no-injury control separately from v2's intentional multi-contact behavior and report any drift. A supported runtime matrix, tolerances/scale and evidence sufficiency require root approval.

Commit only a fully validated boundary.
