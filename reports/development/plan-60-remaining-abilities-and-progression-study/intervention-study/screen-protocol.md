# Limited natural-race screen — proposed, not run

This protocol follows the eight limited Stage0 diagnostics and one seven-case geometry diagnostic. It does not declare full Stage0 correctness, validate Plan59, or adopt any ability constants. Root explicitly permits preparing the screen but must separately review its code and assign compute before execution. The diagnostic geometry did **not** establish a controller-reachable strict-closing pre-finish contact: the candidate closest approach had nonclosing velocity. The inherited finish-first terminal interval remains an approximation, not a demonstrated natural-race defect or a proven general guarantee. Do not change event ordering during this screen.

Proceed serially only under the awarded stretch; before each job inspect host physical memory >=8 GiB, major processes and hash the runner as stated in `screen-execution-plan.md`. Each case uses a seed/raceId and versioned keys exactly as in `protocol-proposal.md`; preserve all rows. No new seeds, parameter tuning, condition variants, retries or automatic broadening. If a physical guard/unresolved outcome, pin drift, error, timeout or memory/cleanup issue occurs, retain that partial result and stop; no healthy subset or subsequent phase is treated as a completed sample.

## Recorded observations and important omissions

Each row records source identity and full input fields, status/guard, actual individual finishes, first/last crossing, each actual contact ID/tick/participants, independent injury-roll key/value/probability/outcome, actual recovery record when present, P opportunity/start/end/controller audit, injury-rating audit, P advice counts, assistance-record count and total draw counts. The seed000 result in each cell/arm additionally retains P's complete sampled trajectory; it is fixed in advance, not selected for appearance. The data records use the processing tick for natural contacts: **the natural output currently does not retain the exact swept fraction**, so do not infer precise contact-at-Guard-boundary or exact count of false predictions. A P contact after P is already injured has no new P injury roll; absence of a roll is not protection. Entry-injured cases have no P new-injury probability and no recovery-extension model; report their P new-injury outcome as inapplicable, never a zero-rate protection result.

The intervention audit records activation opportunities when eligible, keyed draws, starts, ends and controller changes; it does not record all ineligible sampling instants, a full continuous contact-prediction history or every R2/advice overlap at each activation. Advice totals and assistance record counts are context only; they cannot establish overlap, causality or suppression. Per-contact recovery records may be unfinished when a race finishes; report completed durations with their observation denominator and censor/uncompleted counts. Heading/lateral trajectory differences can be examined only in the fixed seed000 witnesses under the proposed compact output; no natural-screen-wide full-trajectory time series is retained. Actual participant collision, injuries and finish order remain distinct from an animation or predicted event.

## Analysis and limits

Predeclared groups are each health/field/stance/arm cell: n=16 healthy or n=8 injured if all complete. Summaries show P contact and new injury counts (Wilson interval for finished cases with independent-seed assumption), contact count distribution, starts/opportunities, eligible Guard-reduced P rolls, recovered/completed episode counts and completed-only recovery duration distribution, P placement and winner/last crossing time distributions. Distributions use minimum, index-floor 25th percentile, median, index-floor 75th percentile, maximum. **Fewer than eight activations is an evidence-sufficiency warning only**, not a guarantee that eight or more establishes reliability, equivalence, or useful power; count relevant actual contacts/recoveries separately. No test of equal ability strength or statistical significance is justified by this exploratory size.

For each cell, compare candidate and none by matching seed, stable race identity and input configuration; report paired P-place difference distribution and number better/same/worse, not an isolated causal estimate. Guard/none contact-level injury comparisons count only P rolls with the same actual contact ID, entrant draw key and draw value. Report how many are matched and discordant; do not call an injury avoided if the contact or draw identity differs, or if a duck was already injured and had no roll. Different ability-induced paths can change later contact/activation opportunities, and these unmatched observations remain in the aggregate with no causal attribution. Self-witnesses, sparse activations, no-op windows, unsuccessful attempts, guard rollback and censoring are findings, not exclusions. No power ranking follows simply from more wins or an insufficient number of opportunities.

`screen-analyze.mjs` accepts `healthy` or `injured` only after all expected files for that phase have a valid start/completion marker and every exact index is present and finished. It checks unique contiguous inputs and refuses to summarize a failed/incomplete phase rather than silently omit rows. It creates one exclusive analysis file per phase; pin analyzer and inputs, capture its bounded launcher receipt, report any failure and do not run it until the corresponding full phase is explicitly complete. Any failed/unresolved case remains in its original JSONL and failure receipt and must be reported directly to root.
