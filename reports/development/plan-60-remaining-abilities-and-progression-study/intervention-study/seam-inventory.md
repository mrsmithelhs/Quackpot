# Study implementation inventory — draft for Stage 0 review

`adapter.mjs` is a report-local copy of the pinned Plan55 reconciled adapter, not a wrapper. Its original relative imports are redirected to read-only pinned Plan55 helpers and the pinned production PRNG; its new `./interventions.mjs` is owned here. Compare with `git diff --no-index --ignore-space-at-eol <Plan55 adapter> <study adapter>`: Windows line-ending differences otherwise obscure the actual edits. The 15-source transitive static import closure is listed in `source-pins.txt`. No source from Plan55 or `src/` is written.

Changes are limited to input validation and player study initialization; temporary intervention state and deterministic opportunity audit; guard prediction and fractional contact injury threshold; contact-triggered post-impulse controller changes; selected injury-rating calculation and audit; end/finish/rollback state; and explicitly exported report-only controlled fixtures. The old `.95` target/reference blocks remain only on the legacy path when `input.intervention` is absent; all new arms including `none` bypass them and use the selected `.9` rating before conversion, corner cap and leader slowdown. `stage0-parity.test.mjs` is intended to confirm no-injury legacy mechanical parity, not injured-path identity.

Quick Recovery performs a **one-time transition** from its current contact acquire/hold episode into its normal recover phase after contact; the resulting path persists after the activation window, because physical movement cannot be undone. Window expiry removes the temporary ability state, not the actual movement. A new contact ends the active window and starts cooldown. Straight Shooter temporarily halves its active contact episode's target angle; at timeout it restores the previously sampled target if that same episode still exists, without snapping heading. A new contact replaces the episode and ends the active effect; at finish it ends. The adjusted acquire/hold threshold is active only while that modifier is active. Actual controller/timing implications need the tests and review; these descriptions are not production decisions.

Guard samples at ticks divisible by 5. Actual contact time is `processingTick − 1 + fraction`; a Guard window protects only if `start < contactTime < end`, excluding the exact activation and end boundaries. Guard expiry is processed relative to the prior interval so a contact just before integer end is not treated as if it happened after expiry; cooldown starts at scheduled end, not late processing. The inherited endpoint resolver excludes a duck that crosses within the processed terminal interval before resolving that endpoint's contacts; no claim is made that it distinguishes a real earlier contact from a later finish in the same interval. That inherited limitation needs explicit source review and/or a future amendment; it must not be concealed by a synthetic fraction injection.

An actual contact's injury draw remains keyed by Plan55 raceId/contactId/entrant; the P factor is applied to its threshold only if Guard is active at that fractional time. Same contact identity is required for paired draw claims. An already injured entrant is initialized as such and does not draw a new injury; no extension transaction is simulated. P entry injury is selected before the first movement step; a new injury is applied beginning on the next tick. Audit exposes sampled rating, uninjured/adjusted top speed and first capped target; a slowdown reference appears only if the relevant condition occurs. A plain arithmetic test is not a full controller/corner witness.

Rollback snapshots already clone all entrant properties; the intervention state/audit is stored inside the player entrant and should therefore restore with it. The added `testGuardAfterIntervention` flag is a **guard-limit test argument**, never a natural-race input: after a real P contact with active intervention it forces an existing error/rollback path. Stage0 asserts existing reference/entrant/audit/draw/trajectory proof fields; lack of coverage on fixed cases is a failure to establish coverage, not a reason to pick another seed. Test-only controlled fixtures deliberately supply sweep endpoints/fractions or reset positions and cannot show a continuous multi-contact path.

The tests and `stage0-fixtures.md` are pending source/execution review. No test or numerical race in this folder has been executed. The exact Stage0 runner/receipt procedure and lock/hashes must be approved and pinned before execution. The Stage1 screen remains a separate decision even if Stage0 succeeds.
