# Production occurrence policy — first integration slice

Source-turn pins: `production-turn-pins.md`. New schema6 opt-in runs only; `messages-v1` must match in run start and envelope. Older absent-policy runs have unchanged behavior. This table is implementation direction, not a claim of delivered messages.

| Communication | Occurrence and stable identity | Evidence and action |
|---|---|---|
| Scheduled work | When a validated five-slot transition first enters a day with a scheduled employed Midday shift, create one `work:shift:<day>` occurrence with revision 1, using that transition's commit sequence for ordering. Initial day one is established by start policy/calendar. No work offer is inferred from phone viewing; preexisting work route stays until adapter is proven. | Message is informational; work keys and existing engine remain sole action route. No overtime offer. |
| Loan statement | A validated `loan_accepted` effect within its committed finance transaction establishes `loan:statement:<loan-id>` revision 1, ordered by commit sequence; text comes from the validated loan, not a user-provided event payload. Later repayment/default updates action availability without creating a delivery. | Read and outstanding are separate. Repayment must freshly prepare and commit existing finance transaction; actual terms shown remain existing authoritative events. |
| Launch invite | For enabled starts, initial policy explicitly establishes `launch:invitation:1` before launch; reply requires existing offer-shown evidence, generated only on meaningful display. Existing invitation remains until parity. | Existing `showLifeInvitation`, `replyLifeInvitation`, `showLifeAcknowledgment` own shown/action/cue. Reply establishes acknowledgment occurrence; no reward on read. |
| Ren | Only validated post-introduction social transitions establish identities from plan/response ID and occurrence. Existing social shown and choices stay authoritative. | Exact per-kind mapping remains to be finalized against the current transition graph before replacing the old route. |
| History | Four fixed authored contacts exist from policy start, read and action-free, without arrival event, finance or Ren relationship. | No event or reward for history display. |

Projection must retain occurrence payloads from reconstructed validated prefix rather than assume current finance/schedule proves earlier deliveries. `message_read` must refer to a current registered revision at its exact prefix; bounds precede expensive race reconstruction and metadata agrees with start. Prefix work ordering should use the first actual transition establishing the relevant day (or start for day 1), never render count. If a transition skips a work day, do not invent a delivery for a day not entered. Financial transaction effect and commit are indivisible; reads occur outside them. All remaining authoritative route replacement stays gated on real parity and lifecycle checks.
