`adapter.mjs` is an isolated synthetic model using an in-memory byte-string store and a promise-based shared lock. `adapter.test.mjs` covers consecutive queued saves, another tab's changed primary, cancel, archive-before-replace and retry, same-ID stale/branched evidence against the actual primary, separate terminal-unsaved and saved runs, full-prefix comparison beyond a truncated timeline, shorter-unverified refusal, one-write empty history plus generation, legacy binding after confirmation, and failed readback after a write. It contains no real run data, browser storage, ZIP dependency, game source import, or UI.

The model is deliberately limited. It does not implement production save validation, browser Web Locks, cross-process tab notifications, real quota, cryptographic canonicalization of arbitrary game events, production ID generation, bounds, ZIP export or actual tab termination. The synthetic JSON digest uses Node crypto and JSON serialization solely to distinguish the modeled prefixes; it is not a production canonicalization specification. A simulated lock is not browser concurrency evidence. The terminal-off case explicitly archives in-memory evidence, then replaces; it does not simulate the asynchronous Receipt UI or tab close. Readback failure means the write's outcome is unknown until reinspection, demonstrated as a proposed assertion. Cancellation prevents binding and replacement; earlier separate ending/Receipt archives are not undone.

Integration seams remain `src/main.js` save/terminal/Receipt/restart and recovery dispatch; `src/core/storage.mjs` primary/backup validation and mutation; `src/core/game-engine.mjs` ID envelope serialization; Welcome restart and view; Settings async result/clear; optional Receipt status.
