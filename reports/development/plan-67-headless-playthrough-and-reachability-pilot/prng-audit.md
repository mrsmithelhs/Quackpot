# PRNG and reproducibility audit — Plan 67 first gate

Static audit of commit `7945bb26ee1a0570d3ac455d5639488447f578a2`, default five-slot schema 5, tutorial shift enabled, race v1 and no Messages policy. Proposed pilot seed `plan67-pilot-001` is a fixed test input, not a sampled or verified route. No randomness was exercised in this audit.

| Source / ownership | Inputs and consumption | Consequence and replay |
|---|---|---|
| Browser seed | `generateRandomSeed` takes two crypto uint32 values; fallback uses `Math.random` plus `Date.now` (`src/main.js:129-136`). Engine constructor fallback is `Date.now` (`game-engine.mjs:112`). | This seed determines gameplay. Pilot explicitly passes its string, matching browser policy/setup rather than pretending to reproduce browser entropy. `run_started` records seed and policy/config (`game-engine.mjs:542`). |
| Root and streams | sfc32 warmed 15 times, fork uses key path, independent of current stream position (`prng.mjs:3-23,55-105`). Constructor forks `draw`, `race`, `event` (`game-engine.mjs:118-124`). | Draw is consumed sequentially; stored root/race/event exist but the default race resolver uses independently derived keyed RNG, not the mutable `rngRace`. `validateSeededDrawHistory` expects root, race and event at initial fork state (`life-replay.mjs:369-397`). Do not advance them artificially. |
| Gacha | Each committed item consumes `rngDraw.next()` for rarity and `rngDraw.int(pool.length)` for identity; pity, duplicate inventory and Down then update (`game-engine.mjs:900-920`). Promotional draws do not advance pity; paid draws do. | Affects owned ducks, payout, future eligibility and Receipt `draw_committed` including conditional odds. | Default race | `runRace` feeds seed, race ID, stance, duck/rest/trial and field into resolver (`game-engine.mjs:1374-1455`). | Work story | `selectWorkStory(seed,id)` creates a separate keyed RNG and picks commute plus two different work beats (`life-story-content.mjs:109-119`). | Changes presented narrative and `story47_shown` evidence; it is not a draw-stream consumer. | Experimental schema 6 | Separate keyed integer race kernel, worker/async reconstruction and `messages-v2` (`race-kernel-v2.mjs:69`, `race-v2/codec.mjs:16`, `main.js:531-548`). | Different policy and storage; excluded pending expansion. Worker completion/cancellation and revision checks are additional ordering inputs, not a default race result. |
| Presentation / incidental identity | Welcome cosmetic timeline defaults to `Math.random` (`ui/welcome-view.js:11`, `ui/welcome/cosmetic-timeline.mjs:4`); UI timers use clock/performance for motion. Default `usageRunId` is crypto generated independently (`main.js:138-145`); `savedAt` uses wall clock (`game-engine.mjs:1988`). | Cosmetic motion is not a gameplay RNG stream; timing can affect which display callbacks actually occur, so do not erase display evidence. Usage identity serves profile tracking and is not passed to gameplay random selection in inspected paths; verify any equality exclusion at the actual comparison seam. `savedAt` may be excluded from strict semantic regeneration under Plan 35; don't broadly strip IDs/log fields or hash chains. |

Transactions clone and publish all four streams with state and log (`game-engine.mjs:611-650`), and envelopes serialize all streams, state, log, schema and time; `fromEnvelope` hydrates them (`game-engine.mjs:1982-2015`). Storage validation and life replay inspect history, not just shape (`storage.mjs:77`, `life-replay.mjs`). The event log chains sequence, type, logical game clock and payload (`event-log.mjs:26-50`); compare complete meaningful events and chain, RNG, state, policy and recipe. A resumed suffix must be compared with uninterrupted execution from the identical prefix, not just final cash. Inspect the precise comparator and all identity references before excluding metadata. Simulated presentation and real browser display must remain separately labeled.

Unknowns: no run or cross-runtime equality was tested; race floating-point drift remains a source of potential replay failure. No conclusion about future/schema 6 streams, browser scheduling, or unexamined presentation dependencies. No network or actual student data involved.
