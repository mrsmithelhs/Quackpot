The observed direction is action → controller → engine transaction/event → render and save; Receipt reads the event history. Rendering additionally reports actual exposures back through engine methods. That feedback edge is legitimate but requires visibility and deduplication ownership. It must not be mistaken for a rule engine living in the view.

## Proposed seams, in priority order

1. **A production integration record, before another architectural abstraction.** Pin selected source/preview revision, label additions/context/placeholders/deferrals, name the replacement seam and3–6 preserved neighbors. Point each to one real route or distinctive observation. This is a small packet section, not a new parallel specification.
2. **A current reachable checkpoint for one changed route.** Reuse the existing ordinary-load/provenance methods after a scoped adaptation; do not transplant their historical parent chain or change old capture bytes to look current. Keep capture identity and current validation separate. A controlled component harness remains useful for layout but cannot replace this route.
3. **A narrow life-session controller boundary when47 exposes the exact need.** Consolidate command→engine→route reconciliation→save and view lifecycle for the new policy, while leaving legacy dispatch intact. Proposed helpers can receive engine/save/render dependencies rather than importing the whole app. Do not preempt the active writer by extracting main.js in parallel. An extraction is worthwhile only if it removes duplicated ownership of a measured boundary without changing events/save behavior.
4. **Presentation lifecycle adapter when two mounted effect consumers need it.** Explicit active/hidden/reduced/paused/destroy signals and optional snapshots; owner at composition root. Start by adapting existing handles, not migrating every view or introducing a framework. Pause policy for audio and weather still needs its own selection.

## Semantic concurrency map

| Work combination | Safe concurrency recommendation |
|---|---|
| Pure Ren SVG extraction + work integration | Concurrent with disjoint paths and a pinned provisional asset API; no implied permission to mount unfinished art. |
| Report-only music composition + source work integration | Concurrent if resource-heavy/browser turns are coordinated and renderer baseline pinned. No production audio imports. |
| Ren/gig mechanism proposals +47 implementation | Design can run concurrently against a named contract version; implementation proposals must be rebased/reviewed after47's final contract. |
|47,46,48 engine/life/storage/Receipt/controller mutations | Serialize writers and commit handoffs. Disjoint helper files still share phase/anchor/replay semantics. |
| Weather/audio host wiring + main controller extraction | Serialize host changes; pure effect helpers can proceed separately after agreed inputs. |
| Tests and preview evidence on a moving shared tree | Pin the source/fixture/server revision. A later HEAD does not inherit prior browser evidence automatically. |

At a shared-contract change, send a compact delta to affected packet owners through authorized orchestration: old/new invariant, exact commit, compatibility choice, invalidated fixtures and required targeted recheck. Require acknowledgment before their next source integration. This review sent no such messages. Worktrees can isolate edits and allow abandonment; they do not settle conflicting Evening meanings or prove that a preview is production-faithful.
